# EBiCS Firmware Technical Reference

## 1. Overview

The EBiCS firmware is an open-source Field Oriented Control (FOC) firmware for Lishui-type BLDC motor controllers commonly used in e-bike applications. It runs on the **STM32F103C8** microcontroller (ARM Cortex-M3) and drives a three-phase brushless motor through IRS2003 half-bridge gate drivers.

The firmware is based on the ST user manual **UM1052** (STM32F PMSM FOC SDK) and was developed using the OpenSTM32 workbench (SW4STM32 toolchain), with initial peripheral configuration generated by STM32CubeMX. It makes extensive use of the CMSIS DSP library (`arm_math.h`) for fixed-point trigonometric and mathematical operations.

### Key Capabilities
- Sinusoidal FOC commutation with current (torque) control
- Hall sensor-based rotor position sensing with interpolation and PLL
- Optional sensorless back-EMF observer (Luenberger-style flux observer)
- Pedal Assist Sensor (PAS) processing with torque sensor and torque-simulation modes
- Throttle input with optional speed control loop
- Regenerative braking (digital or analog brake input)
- Multiple display protocol support (King-Meter, Bafang, Kunteng, EBiCS)
- Hall sensor auto-detection and EEPROM calibration storage
- Motor KV auto-detection
- Speed limiting (EU legal compliance)
- Battery current limiting and over-temperature protection

## 2. Hardware Architecture

### 2.1 Microcontroller

**STM32F103C8T6** — 64 MHz ARM Cortex-M3, 64 KB Flash, 20 KB SRAM.

The system clock is derived from the internal 8 MHz HSI oscillator, divided by 2, then multiplied by 16 via PLL, yielding a 64 MHz system clock (`SystemClock_Config()`).

- **APB1**: 32 MHz (÷2)
- **APB2**: 64 MHz (÷1)
- **ADC clock**: ~10.67 MHz (APB2 ÷ 6)

### 2.2 GPIO Pin Assignments

| Function | Pin | Port | Notes |
|---|---|---|---|
| Hall Sensor 1 | PA0 | GPIOA | Input, pull-up |
| Hall Sensor 2 | PA1 | GPIOA | Input, pull-up |
| Hall Sensor 3 | PA2 | GPIOA | Input, pull-up |
| Throttle (ADC) | PA3 | GPIOA | Analog input (ADC Ch3) |
| Phase Current 1 | PA4 | GPIOA | Analog input (ADC Ch4) |
| Phase Current 2 | PA5 | GPIOA | Analog input (ADC Ch5) |
| Phase Current 3 | PA6 | GPIOA | Analog input (ADC Ch6) |
| Brake | PA15 | GPIOA | Digital input, pull-up (active low) |
| Temperature / Torque (AD1) | PB1 | GPIOB | Analog input (ADC Ch9) |
| LED | PB2 | GPIOB | Output |
| Speed Sensor | PB5 | GPIOB | EXTI falling edge, pull-up |
| PAS Sensor | PB8 | GPIOB | EXTI falling edge, pull-up |
| Light | PB9 | GPIOB | Output |
| Brake Light | PB10 | GPIOB | Output |

### 2.3 Gate Driver

The board uses **IRS2003** half-bridge drivers. These require inverted control pulses for the low-side MOSFETs. Dead time is generated by the gate driver IC, but the firmware also configures a 32-tick dead time in TIM1's Break and Dead-Time Register (`sBreakDeadTimeConfig.DeadTime = 32`).

## 3. Timer Architecture

The firmware uses three hardware timers, each serving a distinct purpose:

### 3.1 TIM1 — PWM Generation (Center-Aligned)

- **Mode**: Center-aligned mode 1 (upcounting and downcounting)
- **Period**: `_T = 2028`, yielding an effective PWM frequency of ~15.8 kHz (64 MHz ÷ (2 × 2028))
- **Channels 1–3**: Complementary PWM outputs driving the three half-bridges
- **Channel 4**: Output Compare, triggers injected ADC conversions at `TRIGGER_DEFAULT = 2020` (near the PWM peak, i.e., center of the low-side ON time, optimal for current measurement)
- **Complementary outputs**: `OCNPolarity = LOW` (inverted for IRS2003 low-side drivers)
- **MOE (Main Output Enable)**: Software-controlled for enabling/disabling all PWM outputs atomically

The PWM duty cycles are set by writing to `TIM1->CCR1`, `TIM1->CCR2`, `TIM1->CCR3` with the values computed by the SVPWM algorithm.

### 3.2 TIM2 — Hall Sensor Timing

- **Prescaler**: 128, yielding a 500 kHz tick rate (64 MHz ÷ 128)
- **Input**: XOR combination of TI1, TI2, TI3 (all three Hall signals combined) via `TIM_TI1SELECTION_XORCOMBINATION`
- **Slave mode**: Reset on edge — the counter resets on every Hall state change, capturing the time between successive Hall events in `TIM2->CCR1`
- **Filter**: 8 (hardware debouncing)
- **Purpose**: Measures `ui16_timertics`, the interval between consecutive 60° electrical steps, used for rotor speed estimation and angle interpolation

### 3.3 TIM3 — Slow-Loop / Regular ADC Trigger

- **Period**: 7813, yielding an ~8.2 kHz interrupt rate (64 MHz ÷ 7813)
- **Master output trigger**: `TIM_TRGO_OC1`, triggers regular ADC1 conversions
- **Purpose**: Drives the regular ADC conversion cycle (battery voltage, throttle, phase current offsets, torque, temperature) and increments software counters for PAS timeout, speed timeout, and the slow control loop

## 4. ADC Subsystem

### 4.1 Dual ADC Configuration

The firmware operates ADC1 and ADC2 in **simultaneous regular + injected** dual mode (`ADC_DUALMODE_REGSIMULT_INJECSIMULT`).

#### Regular Conversions (triggered by TIM3 at ~8 kHz, via DMA)

The 7-channel regular conversion sequence on ADC1 populates the `adcData[8]` buffer:

| Index | Channel | Signal |
|---|---|---|
| 0 | Ch7 | Battery voltage |
| 1 | Ch3 | Throttle (connector SP) |
| 2 | Ch4 | Phase current 1 (for offset calibration) |
| 3 | Ch5 | Phase current 2 (for offset calibration) |
| 4 | Ch6 | Phase current 3 (for offset calibration) |
| 5 | Ch8 | Analog brake (connector AD2) |
| 6 | Ch9 | Temperature or torque input (connector AD1) |

#### Injected Conversions (triggered by TIM1 CH4 at PWM rate ~15.8 kHz)

- **ADC1 injected**: Reads one phase current (dynamically assigned)
- **ADC2 injected**: Reads another phase current (dynamically assigned)
- Injected conversions are triggered at the PWM center to measure current during the active low-side period

### 4.2 Phase Current Offset Calibration

At startup (before PWM is enabled), the firmware averages 32 regular ADC samples for each phase current channel to establish zero-current offsets:
```
ui16_ph1_offset = average of adcData[2]
ui16_ph2_offset = average of adcData[3]
ui16_ph3_offset = average of adcData[4]
```
These offsets are written to the injected channel offset registers (`ADCx->JOFR1`) so that subsequent injected readings are automatically zero-centered.

### 4.3 Dynamic ADC Channel Switching

When `DISABLE_DYNAMIC_ADC` is **not** defined (the default), the firmware dynamically selects which two phase currents to measure based on the rotor angle. The third current is reconstructed by Kirchhoff's current law (I_a + I_b + I_c = 0).

The `dyn_adc_state()` function determines which phase has the highest duty cycle (and thus the shortest low-side ON time, making accurate current measurement impossible for that phase). It sets `MS.char_dyn_adc_state` to one of:

| State | Condition | ADC1 reads | ADC2 reads | Reconstruction |
|---|---|---|---|---|
| 1 | Phase C highest duty | Phase A | Phase B | I_c = -I_a - I_b |
| 2 | Phase A highest duty | Phase C | Phase B | I_a = -I_b - I_c |
| 3 | Phase B highest duty | Phase A | Phase C | I_b = -I_a - I_c |

The ADC trigger point (`TIM1->CCR4`) is also dynamically adjusted to sample when the highest-duty phase is at its switching point, minus `TRIGGER_OFFSET_ADC = 50` timer ticks, to ensure sufficient settling time (`ADC_DUR = 250` ticks minimum).

## 5. Field Oriented Control (FOC)

The core motor control algorithm runs in the injected ADC interrupt at ~15.8 kHz (once per PWM cycle). This is the "fast loop."

### 5.1 FOC Pipeline

The `FOC_calculation()` function implements the standard FOC pipeline:

1. **Clarke transform** (`arm_clarke_q31`): Converts two measured phase currents (I_a, I_b) from the three-phase stationary frame to the two-axis stationary frame (I_alpha, I_beta).

2. **Park transform** (`arm_park_q31`): Rotates I_alpha/I_beta by the electrical rotor angle (theta) into the rotating d-q frame, yielding I_d (flux-producing current) and I_q (torque-producing current).

3. **Low-pass filtering**: Both I_d and I_q are filtered with a first-order IIR filter (time constant ≈ 16 samples):
   ```
   q31_i_q_fil = q31_i_q_fil - (q31_i_q_fil >> 4) + q31_i_q
   MS.i_q = q31_i_q_fil >> 4
   ```

4. **Overcurrent protection**: If `q31_i_q > PH_CURRENT_MAX << 2`, PWM is immediately disabled and the MCU enters an infinite loop (requires hard reset).

5. **PI control** (`runPIcontrol()`): Computes U_d and U_q voltage commands — see §5.2.

6. **Voltage limiting**: The combined voltage vector magnitude is limited to `_U_MAX = 2000`:
   ```
   u_abs = sqrt(u_d² + u_q²)
   if u_abs > _U_MAX: scale both u_d, u_q proportionally
   ```

7. **Inverse Park transform** (`arm_inv_park_q31`): Converts U_d/U_q back to U_alpha/U_beta in the stationary frame.

8. **SVPWM** (`svpwm()`): Computes three-phase switch times from U_alpha/U_beta — see §5.3.

### 5.2 PI Current Controllers

Two independent PI controllers regulate the d-axis and q-axis currents:

#### I_q Controller (Torque)
```c
PI_iq.gain_p = P_FACTOR_I_Q;   // config.h: 10
PI_iq.gain_i = I_FACTOR_I_Q;   // config.h: 2
PI_iq.limit_output = _U_MAX;   // 2000
PI_iq.limit_i = _U_MAX;        // 2000
PI_iq.max_step = 5000;         // max change per cycle
PI_iq.shift = 11;              // fixed-point scaling
```

- **Setpoint**: `i8_direction * i8_reverse_flag * MS.i_q_setpoint` — the signed torque demand
- **Normal mode**: Controls I_q to match the current target
- **Battery current limit mode** (`ui8_BC_limit_flag`): Switches to regulating battery current instead of phase current, using `BATTERYCURRENT_MAX` (config.h: `15000` mA) or `REGEN_CURRENT_MAX` (config.h: `10000` mA) as the setpoint

#### I_d Controller (Flux)
```c
PI_id.gain_p = P_FACTOR_I_D;   // config.h: 10
PI_id.gain_i = I_FACTOR_I_D;   // config.h: 2
PI_id.limit_output = _U_MAX;   // 2000
PI_id.limit_i = 1800;
PI_id.max_step = 5000;
PI_id.shift = 11;
```

- **Setpoint**: Normally 0 (pure torque control; no field weakening). Set to ~200 during autodetect for alignment.

#### PI Controller Implementation

The generic `PI_control()` function:
```
p_term = (setpoint - measured) * gain_p
integral += (setpoint - measured) * gain_i
output = p_term + integral   (with slew rate limiting by max_step)
```

Key safety features:
- Integral part is clamped to `±limit_i`
- Output is clamped to `±limit_output`
- Both integral and output are **reset to zero** when PWM is disabled (MOE bit cleared)

#### Speed PI Controller (optional, `SPEEDTHROTTLE` mode)
```c
PI_speed.gain_p = P_FACTOR_SPEED;   // config.h: 1
PI_speed.gain_i = I_FACTOR_SPEED;   // config.h: 10
PI_speed.limit_output = PH_CURRENT_MAX;
PI_speed.max_step = 50;
PI_speed.shift = 5;
```
When `SPEEDTHROTTLE` is defined, the throttle sets a target speed rather than a target current. The speed PI controller's output becomes the current setpoint for I_q.

### 5.3 Space Vector PWM (SVPWM)

The `svpwm()` function implements SVPWM according to UM1052 Chapter 4.9. It converts the stationary-frame voltage components (U_alpha, U_beta) into three-phase PWM switch times.

```c
U_alpha_scaled = sqrt(3) * T * u_alpha / 16
U_beta_scaled  = -T * u_beta
X = U_beta_scaled
Y = (U_alpha_scaled + U_beta_scaled) / 2
Z = (U_beta_scaled - U_alpha_scaled) / 2
```

Sector detection and switch time calculation:

| Sectors | Condition | switchtime[0] | switchtime[1] | switchtime[2] |
|---|---|---|---|---|
| 1 & 4 | Y≥0, Z<0, X>0 (or inverse) | (T+X-Z)/2 + T/2 | st[0] + Z | st[1] - X |
| 2 & 5 | Y≥0, Z≥0 (or both <0) | (T+Y-Z)/2 + T/2 | st[0] + Z | st[0] - Y |
| 3 & 6 | Y<0, Z≥0, X>0 (or inverse) | (T+Y-X)/2 + T/2 | st[2] + X | st[0] - Y |

The computed `switchtime[0..2]` values are written to `TIM1->CCR1..CCR3` to set the duty cycle of each phase.

### 5.4 Battery Current Estimation

Battery current is estimated from the FOC variables rather than a dedicated shunt:
```c
Battery_Current_accumulated -= Battery_Current_accumulated >> 8;
Battery_Current_accumulated += (i_q * u_abs) >> 11 * CAL_I;
MS.Battery_Current = Battery_Current_accumulated >> 8;
```
Where:
- `CAL_I = 38 << 8` — current calibration factor
- `CAL_V = 15 << 8` — voltage calibration factor
- `CAL_BAT_V = 25` — battery voltage scaling

This is a low-pass filtered approximation of `P_electrical / V_battery`, using the relationship `P = V_q * I_q ≈ V_bus * I_battery`.

## 6. Rotor Position Estimation

The firmware supports multiple commutation modes, defined by the `com_mode` enum:
```c
enum com_mode {Hallsensor, Sensorless_openloop, Sensorless_startkick, Hallsensor_Sensorless};
```

### 6.1 Hall Sensor Commutation

Three Hall sensors provide a coarse 60° electrical position signal. On each Hall transition, the `HAL_TIM_IC_CaptureCallback()` ISR:

1. Reads the 3-bit Hall state: `ui8_hall_state = GPIOA->IDR & 0b111`
2. Determines the transition case (e.g., `64` = state 6→4, `45` = state 4→5, etc.)
3. Looks up the calibrated rotor angle for that transition from `Hall_XX` variables
4. Determines rotation direction from the transition sequence
5. Captures the timer interval (`ui16_timertics`) between Hall events
6. Resets rotation counters for standstill detection

#### Hall Angle Calibration

The six Hall transition angles (`Hall_13`, `Hall_32`, `Hall_26`, `Hall_64`, `Hall_51`, `Hall_45`) are calibrated during the autodetect procedure and stored in emulated EEPROM. They represent the exact q31 rotor angle at each transition, scaled so that -180° = -2^31 and +180° = +2^31.

### 6.2 Angle Interpolation

Between Hall events, the rotor angle must be interpolated for smooth sinusoidal commutation. Two methods are available, controlled by `SPEED_PLL` (config.h: `1`):

#### Linear Interpolation (`SPEED_PLL = 0`)
```c
angle = hall_angle + direction * (10923 * timer_count / timertics) << 16
```
Where 10923 << 16 = 715827883 ≈ 60° in q31 format. This linearly scales between the last and expected next Hall positions.

#### PLL-Based Interpolation (`SPEED_PLL = 1`)

A software Phase-Locked Loop tracks the rotor position continuously:
```c
q31_rotorposition_PLL += q31_angle_per_tic;  // every TIM3 tick (~8 kHz)
```

The `speed_PLL()` function updates `q31_angle_per_tic` at each Hall event using a PI controller:
```c
p_term = (actual_hall_position - PLL_position) >> (P_FACTOR_PLL - speed_adapt)
i_term += (actual_hall_position - PLL_position) >> (I_FACTOR_PLL - speed_adapt)
angle_per_tic = p_term + i_term
```

Config parameters:
- `P_FACTOR_PLL = 14` — proportional gain (right-shift amount, so higher = less gain)
- `I_FACTOR_PLL = 14` — integral gain
- `SPDSHFT = 0` — adaptive speed-dependent gain adjustment

The PLL output is used when the PLL error is consistently small (tracked by `ui_8_PLL_counter > 11`). Otherwise, the system falls back to linear interpolation or six-step commutation.

### 6.3 Six-Step Fallback

When the interval between Hall events exceeds `SIXSTEPTHRESHOLD = 20000` timer ticks (corresponding to very low speed), the system switches to six-step commutation:
```c
q31_rotorposition_absolute = q31_rotorposition_hall + direction * deg_30;
```
This adds a fixed 30° offset to the Hall position to place the voltage vector at the center of the 60° sector — the classical six-step strategy.

### 6.4 Sensorless Back-EMF Observer

For sensorless operation, a nonlinear flux observer estimates the rotor position from measured voltages and currents. The implementation is based on the [Lee-Hong-Nam-Ortega-Praly-Astolfi observer](http://cas.ensmp.fr/~praly/Telechargement/Journaux/2010-IEEE_TPEL-Lee-Hong-Nam-Ortega-Praly-Astolfi.pdf).

The observer state equations (in `observer_update()`):
```
e_alpha = x1 - L * i_alpha
e_beta  = x2 - L * i_beta
err = lambda² - (e_alpha² + e_beta²)
x1_dot = -R * i_alpha + v_alpha + (e_alpha * err) >> gamma
x2_dot = -R * i_beta  + v_beta  + (e_beta  * err) >> gamma
x1 += x1_dot >> dT
x2 += x2_dot >> dT
```

Motor model parameters from config.h (configured for a hoverboard motor):
- `INDUCTANCE = 11` — 3/2 × per-phase inductance (scaled)
- `RESISTANCE = 120` — 3/2 × per-phase resistance (scaled)
- `FLUX_LINKAGE = 2000` — permanent magnet flux linkage (scaled)
- `GAMMA = 13` — observer gain (as a right-shift exponent)

The rotor angle is then extracted from the estimated back-EMF using a lookup-table-based atan2:
```c
MS.teta_obs = atan2_LUT(-e_beta, e_alpha) + SPEC_ANGLE;
```

Where `SPEC_ANGLE` is a motor-specific angular offset to align the observer's reference frame with the physical motor.

The observer also estimates electrical speed by detecting zero-crossings (full 360° revolutions) of the estimated angle and filtering the period.

### 6.5 System State Machine

The system tracks its operating state via `MS.system_state`:

| State | Value | Description |
|---|---|---|
| `Stop` | 0 | Motor stopped, PWM disabled |
| `SixStep` | 1 | Six-step commutation (low speed / fallback) |
| `Regen` | 2 | Regenerative braking |
| `Running` | 3 | Normal FOC operation |
| `BatteryCurrentLimit` | 4 | Battery current limited |
| `Interpolation` | 5 | Linear angle interpolation active |
| `PLL` | 6 | PLL angle estimation active |
| `IdleRun` | 7 | Motor spinning with no load demand |
| `Sensorless` | 8 | Sensorless observer active |
| `OpenLoop` | 9 | Open-loop startup for sensorless mode |

## 7. Input Processing

### 7.1 Pedal Assist Sensor (PAS)

The PAS sensor generates pulses as the rider pedals. It connects to PB8 and triggers an EXTI interrupt on the falling edge.

**Signal processing** (in the main loop when `ui8_PAS_flag` is set):

1. **Debounce**: Events closer than 100 TIM3 ticks are ignored
2. **Period averaging**: `uint32_PAS` is a ÷4 exponential moving average of the PAS pulse period
3. **Duty cycle measurement**: `uint32_PAS_fraction` = percentage HIGH time within each PAS period, used for pedal direction detection
4. **Torque accumulation**: If a torque sensor is present, torque readings are accumulated per PAS pulse

#### Direction Detection (`DIRDET`)

When enabled, the firmware checks the PAS duty cycle against thresholds:
- `FRAC_HIGH = 30` — upper threshold (%)
- `FRAC_LOW = 15` — lower threshold (%)

If the duty cycle falls outside [FRAC_LOW, FRAC_HIGH], the rider is pedaling backwards and the motor output is set to zero.

#### PAS Timeout

`PAS_TIMEOUT = 3000` TIM3 ticks (~375 ms). If no PAS pulse is received within this window, pedaling is considered stopped and the motor current target is set to zero.

### 7.2 Throttle

The throttle is read from ADC channel 3 (`adcData[1]`) and mapped to a current target:
```c
uint16_mapped_throttle = map(adcData[1], THROTTLE_OFFSET, THROTTLE_MAX, 0, PH_CURRENT_MAX);
```

Config parameters:
- `THROTTLE_OFFSET = 920` — ADC value at idle (auto-calibrated at startup)
- `THROTTLE_MAX = 2850` — ADC value at full throttle

#### Throttle Override (`THROTTLE_OVERRIDE`)

When defined (default), the throttle can override the PAS-derived current target:
```c
if (mapped_throttle > current_target_from_PAS)
    current_target = mapped_throttle;
```

#### Speed-Based Throttle (`SPEEDTHROTTLE`)

When defined, the throttle input drives a speed PI controller instead of directly setting current. The throttle value is converted to a speed target:
```c
speed_target = mapped_throttle * SPEEDLIMIT / PH_CURRENT_MAX;
```
The speed PI controller then outputs the phase current setpoint. Below 3 km/h, the controller operates with reduced limits for smooth startup.

### 7.3 Torque Sensor

When `TS_MODE` is defined, the firmware operates in torque-sensor mode. The torque sensor input is read from either AD1 (`TQONAD1` defined) or the SP connector.

The current target is computed as:
```c
target = (TS_COEF * assist_level * torque_cumulated / PAS_period) >> 8
```
Where:
- `TS_COEF = 1200` — torque sensor coefficient (config.h)
- `assist_level` — 0..255, from display
- `torque_cumulated` — averaged torque signal over one crank revolution
- `PAS_period` — cadence information

The torque offset is auto-calibrated at startup: `MP.torque_offset = average + 5`.

### 7.4 Brake Input

Two brake input methods are supported:

#### Digital Brake (default)
The brake lever connects to PA15 (active low, pull-up). When pressed:
```c
brake_flag = !HAL_GPIO_ReadPin(Brake_GPIO_Port, Brake_Pin);
```
Regenerative current is set to the fixed `REGEN_CURRENT = 800` (config.h).

#### Analog Brake (`ADC_BRAKE`)
When defined, the brake uses analog input from `adcData[5]`:
```c
mapped_BRAKE = map(brake_adc, THROTTLE_OFFSET, THROTTLE_MAX, 0, REGEN_CURRENT);
```
This allows proportional regenerative braking.

In both cases, regen is only applied above 6 km/h to prevent stalling, and the brake light output (PB10) is activated.

**Overvoltage protection during regen**: The regen current is ramped down as the battery voltage approaches `BATTERYVOLTAGE_MAX = 53000`:
```c
regen_target = -map(Voltage * CAL_BAT_V, BATTERYVOLTAGE_MAX - 1000, BATTERYVOLTAGE_MAX, regen_target, 0);
```

## 8. Current Target Calculation (Priority Logic)

The main loop computes the motor current setpoint using a priority chain:

1. **Brake (highest priority)**: If brake is engaged, set regen current target (digital or analog). Limited by battery voltage to prevent overcharging.

2. **Undervoltage protection**: If `MS.Voltage < VOLTAGE_MIN` (config.h: `1320`, representing ~33V), current target = 0.

3. **Push assist**: If push assist flag is set (from display), current target = `PUSHASSIST_CURRENT = 300` (config.h).

4. **Normal riding (lowest priority)**:
   - In **torque sensor mode** (`TS_MODE`): Current proportional to pedal torque × cadence × assist level
   - In **PAS simulation mode**: Current proportional to display assist level, activated when PAS pulses are detected (cadence > 0)
   - **Throttle override**: If throttle > PAS-derived target, throttle takes over

### 8.1 Speed Limiting (`LEGALFLAG`)

When `LEGALFLAG` is defined (default), the current target is progressively reduced as speed approaches the legal limit:
```c
target = map(speed, speedLimit * 100, (speedLimit + 2) * 100, target, 0);
```
Config: `SPEEDLIMIT = 25` km/h. The current ramps to zero over a 2 km/h window (25–27 km/h).

When pedals are not turning, the limit drops to 5–7 km/h:
```c
target = map(speed, 500, 700, target, 0);
```

### 8.2 Temperature Derating

The current target is further reduced based on motor temperature:
```c
MS.i_q_setpoint = map(MS.Temperature, 120, 130, target, 0);
```
This linearly ramps power to zero between 120°C and 130°C.

### 8.3 Battery Current Limiting

Estimated battery current is monitored within `runPIcontrol()`:
- If `Battery_Current > BATTERYCURRENT_MAX` (15000 mA) → limit flag set
- If `Battery_Current < -REGEN_CURRENT_MAX` (10000 mA) → limit flag set

When the limit flag is active, the I_q PI controller switches from phase current control to battery current control with appropriate limits. The flag resets with a 7/8 hysteresis to avoid oscillation.

## 9. Speed Measurement

### 9.1 Internal Speed (from Hall sensors)

The Hall sensor timer (TIM2 at 500 kHz) measures the interval between Hall events. Speed in timer ticks is filtered:
```c
uint32_tics_filtered -= uint32_tics_filtered >> 3;
uint32_tics_filtered += ui16_timertics;
MS.Speed = uint32_tics_filtered >> 3;
```

Conversion to km/h:
```c
speed_x100 = WHEEL_CIRCUMFERENCE * 50 * 3600 / (6 * GEAR_RATIO * tics)
```
Where:
- `WHEEL_CIRCUMFERENCE = 1250` mm (config.h)
- `GEAR_RATIO = 44` — 10 poles × 4.4 mechanical ratio (config.h)
- Factor 6: Hall events per electrical revolution
- `SPEEDFILTER = 1` — additional exponential averaging (config.h)

### 9.2 External Speed Sensor

When `SPEEDSOURCE = EXTERNAL` (config.h: `1`), a separate wheel speed sensor on PB5 provides speed data:
```c
speed_x100 = WHEEL_CIRCUMFERENCE * 8 * 360 / (PULSES_PER_REVOLUTION * tics)
```
With `PULSES_PER_REVOLUTION = 1` (config.h).

The external speed counter has a timeout of 128000 TIM3 ticks (~16 seconds), after which speed is considered zero.

### 9.3 Electrical RPM (ERPS)

For internal computations:
```c
ui16_erps = 500000 / ((uint32_tics_filtered >> 3) * 6);
```

## 10. Autodetect and Calibration

### 10.1 Hall Sensor Autodetect

The `autodetect()` function determines the relationship between Hall sensor states and rotor electrical angle. It is triggered at startup by holding the brake and throttle simultaneously for ~7 seconds.

**Procedure**:
1. Enable PWM and set I_d to ~2A (open-loop alignment current)
2. Slowly rotate the electrical angle through 1080° (3 full electrical revolutions) in 1° steps with 5 ms delay
3. At each Hall state transition, record the current rotor angle for that transition
4. Determine rotation direction from the sequence of Hall transitions
5. Store the 6 transition angles and Hall order (direction) in emulated EEPROM

The stored variables:
- `EEPROM_POS_HALL_ORDER`: +1 or -1 (rotation direction mapping)
- `EEPROM_POS_HALL_45..64`: Six calibrated transition angles (upper 16 bits of q31 values)

### 10.2 KV Detection

After autodetect completes, the firmware automatically measures the motor's voltage constant (KV):
1. Gradually increase I_q from 30 upward
2. Measure speed and applied voltage
3. Compute: `KV = (speed × T) / (Voltage × u_q)`
4. Stop when `u_abs > 1900` (approaching voltage limit)
5. Store KV in EEPROM

KV is used for feed-forward initialization of the PI controller integral term when re-enabling PWM, allowing smoother transitions from stopped to running.

### 10.3 Standstill Position

`get_standstill_position()` reads the current Hall state and looks up the corresponding calibrated angle, providing an initial rotor position estimate before the motor starts turning.

## 11. EEPROM Emulation

The STM32F103 lacks true EEPROM. The firmware uses ST's flash-based EEPROM emulation library, which uses the last two 1 KB flash pages (pages 126–127, at addresses `0x0801F800`–`0x0801FFFF`).

Stored variables (13 total, `NB_OF_VAR = 0x0D`):

| Address | Variable | Description |
|---|---|---|
| 0x00 | Hall order | Motor direction mapping (+1/-1) |
| 0x01–0x06 | Hall_45..Hall_64 | Six calibrated Hall transition angles |
| 0x07 | KV | Motor voltage constant |
| 0x08–0x0C | KT_Bx | Kunteng display configuration bytes |

## 12. Display Communication

The firmware supports four display protocols, selected at compile time via `DISPLAY_TYPE` in config.h. All use UART1 at protocol-specific baud rates.

### 12.1 King-Meter Protocol (`DISPLAY_TYPE_KINGMETER_618U` / `_901U`)

- **Baud rate**: 9600
- **Library**: `display_kingmeter.c/h` (by Michael Fabry)
- **Sub-protocols**: 618U (simple, 6-byte RX / 8-byte TX) and 901U / KM5s (extended, up to 64-byte RX / 13-byte TX)

**Data sent to display**:
- Battery status (normal/low)
- Wheel time (ms per revolution, for speedometer)
- Error codes (overtemperature, internal overtemperature, none)
- Battery current (× 0.1A)

**Data received from display**:
- Assist level (0–255)
- Headlight on/off
- Push assist on/off
- Speed limit, current limit (from settings)

### 12.2 Bafang Protocol (`DISPLAY_TYPE_BAFANG`)

- **Baud rate**: 1200
- **Library**: `display_bafang.c/h` (by Jens Kießling)
- **Compatible with**: BBS01/BBS02 displays (C965), Prophete Entdecker 'Blaupunkt' display

**Data sent**: Battery level (5 thresholds from config.h), wheel time, power
**Data received**: Assist level (0–9, mapped via `assist_factor[]`), headlight, push assist

Battery level thresholds (config.h):
```c
BATTERY_LEVEL_1 = 323000   // ~32.3V
BATTERY_LEVEL_2 = 329000
BATTERY_LEVEL_3 = 344000
BATTERY_LEVEL_4 = 368000
BATTERY_LEVEL_5 = 380000   // ~38.0V
```

### 12.3 Kunteng Protocol (`DISPLAY_TYPE_KUNTENG`)

- **Baud rate**: 9600
- **Library**: `display_kunteng.c/h`
- **Features**: Configuration of many controller parameters via display (wheel size, max speed, current limit, etc.)
- Push assist is triggered when assist level = 6

Configuration is stored in EEPROM variables `EEPROM_KT_B0..B10`.

### 12.4 EBiCS Protocol (`DISPLAY_TYPE_EBiCS`)

- **Baud rate**: 9600
- **Paging system**: Sends 4 different data pages in round-robin at ~4 Hz (every 4th slow-loop iteration)
- Currently partially implemented

### 12.5 Debug Mode (`DISPLAY_TYPE_DEBUG`)

- **Baud rate**: 56000
- **Output**: CSV-formatted diagnostic data via UART at ~16 Hz
- Supports `FAST_LOOP_LOG`: Logs 300 samples of fast-loop variables (phase currents, d/q currents, d/q voltages) for offline analysis

## 13. Main Loop and Timing Architecture

### 13.1 Interrupt Priorities and Execution Frequency

| Source | Frequency | Handler | Purpose |
|---|---|---|---|
| TIM1 CC4 → ADC injected | ~15.8 kHz | `HAL_ADCEx_InjectedConvCpltCallback` | FOC calculation (fast loop) |
| TIM3 overflow | ~8.2 kHz | `HAL_TIM_PeriodElapsedCallback` | Counters, PLL update, regular ADC trigger |
| TIM2 input capture | Variable | `HAL_TIM_IC_CaptureCallback` | Hall sensor events |
| EXTI 5/8 | Variable | `HAL_GPIO_EXTI_Callback` | PAS and speed sensor pulses |
| UART RX idle | Variable | `UART_IdleItCallback` | Display message received |

### 13.2 Slow Loop (~16 Hz)

Within the main `while(1)` loop, a slow control loop runs every 500 TIM3 ticks (~62 ms):

- **LED toggle**: Heartbeat indicator
- **Observer delay filter update**: Computes sin/cos compensation for observer delay at current speed
- **Sensorless transition**: Switches from Hall to sensorless mode when speed exceeds threshold
- **Idle detection**: If motor runs without load for >60 seconds (`uint16_idle_run_counter > 960`), PWM is disabled
- **Temperature reading**: NTC thermistor via ADC (if `R_TEMP_PULLUP` ≠ 0), uses a logarithmic approximation for 10 kΩ NTC with β=3900K
- **Battery voltage update**: `MS.Voltage = adcData[0]`
- **Speed timeout**: If external speed counter exceeds 128000, speed = 0
- **Individual mode profile**: Speed-dependent assist curves (`INDIVIDUAL_MODES`)
- **Motor standstill detection**: If no Hall events for ~1 second (counter > 7999), PWM is disabled
- **Display page transmission**: Protocol-specific periodic messages

### 13.3 PWM Enable/Disable Logic

PWM is **enabled** (`SET_BIT(TIM1->BDTR, TIM_BDTR_MOE)`) when:
- Current setpoint > 0 AND PWM is currently disabled
- Initial PWM values are set to midpoint (1023)
- PI integral is pre-loaded with KV-based feed-forward estimate
- TIM2 counter is reset, standstill position is read

PWM is **disabled** (`CLEAR_BIT(TIM1->BDTR, TIM_BDTR_MOE)`) when:
- Motor is not turning (standstill detected via Hall counters)
- Idle run timeout expires (60 seconds)
- Overcurrent detected in FOC loop (permanent disable until reset)

## 14. Safety Features

### 14.1 Overcurrent Protection
Hardware-level: If `i_q > PH_CURRENT_MAX * 4`, PWM is disabled and the MCU enters an infinite loop.

### 14.2 Battery Current Limiting
Software PI controller switches to battery current regulation when `BATTERYCURRENT_MAX` (15 A) is exceeded.

### 14.3 Undervoltage Lockout
Motor disabled when `MS.Voltage < VOLTAGE_MIN` (config.h: `1320` = ~33V).

### 14.4 Overvoltage Protection (Regen)
Regen current is linearly reduced to zero as battery voltage approaches `BATTERYVOLTAGE_MAX` (53V).

### 14.5 Over-temperature Protection
Current target is linearly reduced between 120°C and 130°C motor temperature. Display protocol reports overtemperature errors.

### 14.6 Startup Safety
At power-on, the firmware waits until the throttle ADC reads below `THROTTLE_OFFSET` before entering the main loop, preventing unintended motor activation.

### 14.7 Standstill Detection
If no Hall events occur for ~1 second, PWM is disabled. This prevents continuous current flow into a locked rotor.

### 14.8 Speed Limiting
EU-legal speed limiting (`LEGALFLAG`) progressively cuts power at `SPEEDLIMIT` (25 km/h). Without pedaling, the limit drops to 5–7 km/h.

## 16. Build System

The firmware can be built with:
- **SW4STM32 (OpenSTM32)**: Eclipse-based IDE with ARM GCC
- **Makefile**: Standalone GNU Make build (`makefile`, `Makefile_cas`)
- **Make directory**: Alternative build configuration in `make/` with separate linker scripts for STLINK and UART flashing

Linker scripts:
- `STM32F103C8Tx_FLASH.ld` — Standard flash layout
- `STM32F103C8Tx_FLASH_Bootloader.ld` — With bootloader offset
- `make/STLINK_FLASH.ld` / `make/UART_FLASH.ld` — Alternative configurations

A Java-based parameter configurator (`JavaConfigurator/`) provides a GUI for generating `config.h` files.
